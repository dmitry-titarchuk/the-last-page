Учебный проект для демонстрации готового игрового среза. Браузерный 3D-сокобан: пять карт по семь комнат, движение по клеткам, толкание сундуков с книгами, отмена хода и перезапуск. При открытии страницы появляется вступительный комикс из трёх кадров: письмо хранителя, загадка библиотеки, цель головоломок вместе с управлением. «Войти в историю», «Пропустить» или Escape закрывают вступление и открывают первую комнату. Вступление можно перечитать из меню, не теряя текущую комнату и ходы.

## Запуск

Нужен Node.js 22 или новее и браузер с WebGL 2.

```sh
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. Для другого порта: `PORT=5174 npm run dev`.
Запуск через двойной клик по HTML не поддерживается: модули загружаются через локальный сервер. После установки Three.js игра не требует доступа к внешним CDN.

## Установка на телефон и офлайн

Игра — PWA с собственными иконками и отдельным окном без адресной строки. На Android в поддерживающем установку браузере во вступлении появляется кнопка установки, а после закрытия вступления — предложение установить приложение. Кнопка вызывает системный диалог установки, когда браузер разрешает его показать. На iPhone предложение объясняет установку через «Поделиться» → «На экран Домой»; программного системного диалога там нет. В меню игры установка доступна повторно. «Позже» откладывает автоматическое предложение на семь дней; в установленном приложении оно скрыто.

Для телефона нужен **HTTPS с доверенным сертификатом**. `http://localhost` допускается только на самом устройстве; открытие `http://192.168.…:5173` с телефона позволяет играть онлайн, но не включает PWA и офлайн. Для проверки на телефоне используйте HTTPS-домен, HTTPS-туннель или сервер с сертификатом, которому доверяет телефон. Один manifest не может заставить браузер установить полноценное приложение: способ установки зависит от платформы и браузера.

При первом открытии все ресурсы игры, Three.js, 35 комнат и каталог моделей сохраняются в кеше. В меню отображается «Все 35 комнат сохранены — можно играть офлайн» только после успешной установки service worker. После этого можно отключить интернет и закрывать/открывать приложение. Текущая комната, ходы, история отмены и пройденные комнаты сохраняются локально. Очистка данных сайта удаляет кеш и сохранения; браузер также может вытеснить данные при нехватке места. После подтверждения установки игра запрашивает постоянное хранилище, если браузер поддерживает его.

Новая версия загружается в фоне и предлагает «Обновить приложение» в меню. Кнопка активирует обновление и перезагружает игру с восстановлением партии. Во время партии новая версия сама её не прерывает. Все файлы берутся из кеша одной версии, чтобы HTML и JavaScript не смешивались.

Перед публикацией или после изменения файлов:

```sh
npm ci
npm run build
npm run check:pwa
```

`npm run build` собирает готовый статический сайт в `dist/` вместе с необходимыми файлами Three.js. `npm run dev` и `npm run dev:lan` собирают PWA автоматически перед запуском. `build:pwa` генерирует `sw.js` с перечнем ресурсов и версией кеша, вычисленной по содержимому. Не редактируйте `sw.js` вручную: исходник — `scripts/service-worker.js`.

Публикуйте содержимое `dist/` на HTTPS-хостинге. Игра поддерживает как корень домена, так и папку репозитория, например `https://username.github.io/the-last-page/`: ресурсы и манифест используют относительные пути, область service worker и кеш привязаны к папке приложения. Сервер должен отдавать `.webmanifest` как `application/manifest+json`, `.js` как JavaScript и `.png` как `image/png`. Если хостинг позволяет, отключите долгосрочный HTTP-кеш для `sw.js`; регистрация service worker также использует `updateViaCache: 'none'`. На хостинге с пофайловой загрузкой публикуйте ресурсы и HTML перед `sw.js`. Каталог моделей на статическом хостинге находится по адресу `models.html`.

Проверка на телефоне: открыть HTTPS-страницу, дождаться готовности офлайн в меню, установить приложение, включить авиарежим, закрыть и снова открыть игру с её иконки. Сделать ход, закрыть/открыть приложение и убедиться, что ход восстановлен и «Отменить» работает. Проверка обновления: изменить файл, выполнить `build:pwa`, опубликовать, вернуться в игру и нажать «Обновить приложение» в меню.


## Публикация на GitHub Pages

В проекте уже есть `.github/workflows/pages.yml`. Он устанавливает зависимости, запускает тесты, собирает `dist/` и публикует только готовые файлы сайта. `node_modules/` и `dist/` вручную в Git добавлять не нужно. Инструкция соответствует [публикации через GitHub Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

1. На GitHub выберите **New repository**, имя `the-last-page` (или любое другое), видимость **Public**. Не добавляйте README, `.gitignore` и лицензию через форму: репозиторий должен быть пустым. Нажмите **Create repository**.
2. В терминале проекта выполните команды ниже, заменив `YOUR_LOGIN` своим логином GitHub. Git в проекте уже инициализирован; ветку переименовываем в `main`.

   ```sh
   git add .
   git commit -m "Prepare game PWA for GitHub Pages"
   git branch -M main
   git remote add origin https://github.com/YOUR_LOGIN/the-last-page.git
   git push -u origin main
   ```

   Если выбрали другое имя репозитория, замените `the-last-page` в адресе. Для отправки потребуется авторизация в GitHub; пароль аккаунта для Git по HTTPS не используется. Можно отправить изменения через интеграцию GitHub в IDE. Если `origin` уже существует, проверьте `git remote -v` и вместо `remote add` используйте `git remote set-url origin ...` с нужным адресом.

3. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
4. Откройте **Actions → Deploy game to GitHub Pages → Run workflow**, выберите `main` и нажмите **Run workflow**. Первый автоматический запуск мог завершиться ошибкой, если Pages ещё не был включён; ручной запуск после настройки решает это.
5. Дождитесь зелёного статуса задач `build` и `deploy`. Ссылка на сайт появится в **Settings → Pages** и в результате задачи публикации. Ожидаемый адрес: `https://YOUR_LOGIN.github.io/the-last-page/`.
6. Откройте этот адрес на телефоне. В меню дождитесь сообщения о готовности офлайн, установите приложение, включите авиарежим и повторно откройте его с иконки.

Дальнейшие обновления: `git add .`, `git commit -m "Update game"`, `git push`. Workflow запускается на основной ветке `main` или `master`; после публикации новая версия предлагается через «Обновить приложение» в меню игры. Публикация на самом GitHub будет проверена при первом запуске workflow; локально можно проверить сборку командой `npm run build`.

Служебный каталог: http://127.0.0.1:5173/models. Показывает все модели с названиями и ID из кода, включая отдельный декор и игровые объекты. Можно искать и фильтровать модели, выбирать длину мебели, генерировать новый вариант, вращать и увеличивать модель, включать каркас. Колесо или жест двумя пальцами меняют масштаб, перетаскивание вращает; стрелки и клавиши `+`/`-` работают при фокусе на 3D-просмотре. Ссылка с фрагментом сохраняет выбранные ID и длину, но не случайную композицию.

## Управление

- Стрелки или WASD — движение по направлениям сетки.
- На телефоне свайп в любом месте игрового экрана — один ход по ближайшему видимому направлению сетки, с учётом наклона камеры. Тапы по кнопкам сохраняют их обычное действие.
- Перетаскивание мышью на поле или двумя пальцами в любом месте игрового экрана вверх и вниз — наклон камеры.
- Z или «Отменить» — отмена последнего успешного хода.
- «Заново» — перезапуск текущей комнаты.
- После победы — «Следующая комната». Последняя комната карты ведёт на следующую карту.
- «Меню» открывает горизонтальную полку из пяти старинных карт: детективная книга, морское приключение, готическая сказка, забытый роман и библиотека. На каждой карте семь комнат. Карты открываются последовательно после прохождения всех комнат предыдущих карт; закрытые показаны свитками.
- Выбор карты открывает маршрут: комнаты соединены дорожкой, миниатюры повторяют схемы уровней. Следующая комната доступна после прохождения предыдущей, пройденные можно повторять.
- Обе полки прокручиваются свайпом или перетаскиванием мышью. Полоса прокрутки появляется только во время прокрутки; отпускание после перетаскивания не выбирает карту или комнату.
- Прогресс сохраняется в браузере; повторное прохождение его не стирает. Если хранилище недоступно, прогресс действует до перезагрузки страницы.

## Проверка

```sh
npm test
npm run check:levels
```

Проверка карт ищет решения обходом в ширину по толчкам с отсечением тупиков. Она минимизирует число толчков; длина пути героя может быть больше минимальной. Обозначения: U — вверх, D — вниз, L — влево, R — вправо.

## Устройство

- `src/levels.js` — карты и подготовленные сюжетные тексты. Все 35 комнат взяты из `DavidWSkinner Microban.sok` (Microban, David W Skinner); задачи 1–35 идут в исходном порядке, по семь на карту. Номера исходных задач указаны в `source`.
- `src/game.js` — правила и состояние, независимые от 3D.
- `src/scene.js` — управление Three.js-сценой, камера, анимации и жизненный цикл ресурсов.
- `src/model-factory.js`, `src/furniture-models.js`, `src/model-registry.js` — независимые от WebGL генераторы и общий список моделей для игры и каталога.
- `src/perimeter.js` — правила размещения мебели; `src/model-resources.js` — освобождение общих материалов, геометрии и текстур.
- `src/app.js` — управление, полка карт и переходы между комнатами.
- `src/intro.js` — векторные иллюстрации вступительного комикса; текст и оформление находятся в `index.html` и `styles.css`. Пока вступление открыто, управление игрой приостановлено.
- `src/atlas.js` — локации, графика карт, миниатюры и сохранение прогресса. Для новых комнат добавьте данные в `src/levels.js` и их ID в `levelIds` нужной локации: маршрут подстраивается под любое количество комнат, пустой свиток автоматически разворачивается.
- `scripts/server.mjs` — локальный сервер файлов игры; `scripts/site-assets.mjs` — общий список ресурсов сервера, сборки и офлайн-кеша.
- `src/pwa.js`, `manifest.webmanifest`, `scripts/service-worker.js` — установка, офлайн-кеш и обновления PWA.
- `src/session.js` — сохранение и проверяемое восстановление текущей партии вместе с историей отмены.

Показ сюжетных страниц между комнатами и полный экран окончания относятся к следующему этапу. Сюжетные тексты подготовлены как данные, но пока не показываются при прохождении.

Общий замысел полной игры: [PLAN.md](PLAN.md). Первоначальный минимальный объём и фактический результат среза: [MVP.md](MVP.md).
